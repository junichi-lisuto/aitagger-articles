# aitagger-tools-site

**AIタッガーをご契約中のお客様向けの、お役立ちツール公開サイト。**

AIタッガー本体では扱わない周辺作業（CSV加工・他ツール連携・画像変換）を
ブラウザで終わらせるツールと、その使い方、AI検索まわりの情報を置く。

```
mockups/   モックアップHTML（1画面1ファイル）
tools/     実装済みツール（1ツール1フォルダ、index.html）
```

作業のルールは `CLAUDE.md` に書いてある。

## 現在の状態

- トップページ（ツール8本は仮置き・実在しない、モックアップのみ）
- ツール詳細の型（CSV列エディタ、モックアップのみ）
- 生成AI用 商品説明文ツール（実在するツールをブラウザ版として設計したもの、モックアップのみ）
- **`tools/rakuten-attribute-align/`** — 属性整列ツール（実装済み）。元データCSVとAIタッガー処理後CSVを突合し、商品属性の並びを整列する。移植元: `ピンポイント系\楽天AIタッガー属性整列ツール_全項目対応版.py`
- **`tools/csv-text-cleaner/`** — CSVテキストクリーナー（実装済み）。CSVの指定列から文字列を削除・置換する。元は削除ツールと置換ツールの2本だったが、置換後文字列を空欄にすると削除になるロジックのため1ツールに統合。プリセットはブラウザのlocalStorageに保存。移植元: `説明文系\説明文削除ツール\CSVテキストクリーナー.py` ／ `説明文系\説明文置換ツール\説明文置換ツール.py`
- **`tools/result-column-filter/`** — 結果列フィルタ（実装済み）。AIタッガー処理後CSVの「結果」列を見て、変更・タグ追加があった商品の行をまとめて抽出する。元は「変更」検出用と「タグ追加」検出用の2本だったが、パターン切替のプリセット式（＋自由入力）に統合。移植元: `オートカテゴリ\オートカテゴリされた商品だけ抽出.py` ／ `【詳細版専用】タグ追加された商品だけ抽出\オートタグされた商品だけ抽出.py`
- **`tools/duplicate-product-splitter/`** — 重複商品振り分けツール（実装済み）。2つのCSVを比較し、両方に存在する商品を除いて片方にしかない商品だけを1つのCSVにまとめる。移植元: `ピンポイント系\2つのCSVを選んでどちらにも載ってる商品を削除.py`
- **`tools/csv-row-filter/`** — CSV行抽出ツール（実装済み）。列・検索方法（含む／完全一致／正規表現／数値比較など）・検索文字列を組み合わせて行を絞り込む。複数条件のAND/OR、プレビュー機能あり。移植元: `CSV行抜粋（条件指定）\csv_cutter.py`
- **`tools/attribute-delete-keep/`** — 属性削除／残すツール（実装済み）。指定した商品属性だけを削除する、または指定した属性だけを残す。9本あった属性削除ツール群のうち、両モードを統合した最新版1本を移植元に採用（残り8本は前バージョンまたは部分機能のため対象外、うち2本は顧客名ハードコードがあり別途要対応）。移植元: `【削除】属性削除ツール\属性削除／残す統合.py`
- **`tools/capacity-weight-annotator/`** — 容量・重量補完ツール（実装済み）。説明文中の「180ml×3本」等の表記を検出し、単品量・総量の注記を自動で書き足す。楽天CSV・Yahoo CSVの両対応。元Pythonの実際の挙動（ラベル文字の巻き込まれ方など、コメントの理想例とは食い違う細かな副作用）まで一致することを単体テストで確認済み。移植元: `ピンポイント系\容量重量補完.py`
- **`tools/range-to-average/`** — 範囲表記→平均値ツール（実装済み）。説明文中の「10～20cm」のような範囲表記を平均値1つの数値に書き換える。対応する区切り記号・単位記号は元Pythonの正規表現と厳密に一致させた（全角チルダ「～」のみ対応、波ダッシュ「〜」は非対応という仕様も含む）。移植元: `説明文系\説明文の範囲指定表記を平均値に修正.py`
- **`tools/crossmall-optimizer/`** — CROSSMALL列削除ツール（実装済み）。元CSVとAIタッガー処理後CSVを突合し、一元管理システムCROSSMALL向けの列構成に絞り込む。ジャンルID不一致時のテンプレート採用・エラー商品除外という元ツール独自のロジックまで単体テストで一致を確認。移植元: `一元管理ツール系\CROSSMALL列削除\CROSSMALL最適化.py`
- **`tools/itemrobot-optimizer/`** — itemrobot列削除ツール（実装済み）。CROSSMALL列削除ツールと同系統の突合ロジックだが、一元管理システムitemRobot向けの仕様差（「定義」列を除外しない、商品名列を含む、出力文字コードが常にShift_JIS固定）を反映。移植元: `一元管理ツール系\itemrobot列削除\itemrobot最適化.py`
- **`tools/dimension-transfer/`** — 寸法転記ツール（実装済み・一部範囲限定）。楽天商品CSV（PC/スマホ用商品説明文）からサイズ別実寸を抽出し、バリエーション項目選択肢へ転記する。透け感の自動付記、裸の「バスト」記載を肩幅・袖幅・ウエスト等との比率から平置き身幅／周囲寸法へ判定する機能も含む。元ツールは21962行・554関数（同名関数の再定義パッチがv102〜v156まで積み重なる構造）だったため、実際に`main()`から到達可能な337関数だけを行順に抽出したうえで移植した。**移植範囲は限定的**：アパレル・雑貨・ランジェリー向けの寸法抽出・SKU照合・透け感・バスト身幅判定は移植したが、v126以降に追加された寝具（ベッド・マットレス）・家具・ペット用品専用のWHD(幅×奥行×高さ)寸法サブシステムは、AIタッガー利用者（EC/アパレル中心）の想定用途から外れるため対象外とした。単体テストは実際のPythonを実行して`normalize_size_symbol`・`get_size_aliases`・`build_dimension_text`・`extract_label_value_pairs`・透け感判定・バスト比率判定の出力をJS版と突合し一致を確認したが、HTML表（`<table>`）からの抽出パターン1件でPython側の挙動（複数サイズの値がすべて同じ値に潰れる)を再現しておらず、JS版はテーブルを素直に解析する（差異は既知・意図的）。移植元: `ユーザーにも役立つ\寸法転記ツール\寸法転記スクリプト.py`

## 元ツールの棚卸し

サポート担当が作成してきた自作ツール一式（ダウンロード「自作ツール」ZIP、全53件）を調査し、
公開可否・対応事項を整理済み。個社名・APIキーがハードコードされたものを複数検出しており、
移植の際は毎回この棚卸し結果に照らして確認すること（詳細は矢頭さんが保持する棚卸し表を参照）。

## なぜ Sales Console と分けたか（2026-09-11）

`dev\gas-sales-console` は社内向けで顧客情報を扱う。
こちらは**社外のお客様が読む**ため、顧客情報を1バイトも置かない。
規律が正反対なので同じリポジトリに置かない。

デプロイ先も違う（GAS / 静的サイト）ので、`clasp` を誤って叩く経路も作らない。
